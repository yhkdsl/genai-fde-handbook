§ 2.4첫 호출과 비용 계측

Ch.1에서 만든 계측 습관을 여기서 실제 응답에 연결한다.

from google import genai
from google.genai import types

client = genai.Client(vertexai=True, project=PROJECT, location="us-central1")

resp = client.models.generate_content(
    model="gemini-2.5-flash",
    contents="RAG를 한 문장으로 설명해줘",
    config=types.GenerateContentConfig(
        system_instruction="너는 간결한 기술 문서 작성자다.",
        temperature=0.2,
        max_output_tokens=512,
    ),
)

print(resp.text)

u = resp.usage_metadata
print(u.prompt_token_count, u.candidates_token_count, u.total_token_count)

usage_metadata에 실제로 있는 필드 (SDK 확인)

필드의미과금
prompt_token_count입력 토큰입력 요율
candidates_token_count출력 토큰출력 요율
cached_content_token_count캐시에서 재사용된 입력1/10 요율
thoughts_token_count추론(thinking) 토큰출력 요율로 과금
tool_use_prompt_token_count툴 호출에 쓰인 입력입력 요율
total_token_count합계—
thinking 토큰이 비용 사고의 주범이다

Gemini 2.5 계열은 답을 내기 전에 내부적으로 "생각"을 한다. 그 토큰은 resp.text에 보이지 않지만 출력 요율로 과금된다.

즉 "응답이 3줄인데 왜 비용이 이렇게 나오지?" 의 답이 대개 여기 있다. thoughts_token_count를 계측에 포함하지 않으면 비용 추정이 실제보다 낮게 나온다. 고객에게 ROI를 제시하는 자리에서 이건 치명적이다.

제어는 GenerateContentConfig(thinking_config=...)로 한다. Ch.4에서 다룬다.

계측을 포함한 래퍼

PRICES = {  # USD per 1M tokens — Vertex AI 공식 가격표, 2026-07 확인
    "gemini-2.5-flash": {"in": 0.30, "out": 2.50, "cached": 0.03},
    "gemini-2.5-pro":   {"in": 1.25, "out": 10.00, "cached": 0.13},
}

def cost_of(model: str, u) -> float:
    p = PRICES[model]
    cached = u.cached_content_token_count or 0
    fresh_in = (u.prompt_token_count or 0) - cached
    # thinking 토큰은 출력 요율로 과금된다
    out = (u.candidates_token_count or 0) + (u.thoughts_token_count or 0)
    return round(
        fresh_in / 1e6 * p["in"] + cached / 1e6 * p["cached"] + out / 1e6 * p["out"], 8
    )

병렬 호출 — Ch.1의 gather가 여기서 쓰인다

import asyncio

async def ask_many(questions: list[str]) -> list[str]:
    tasks = [
        client.aio.models.generate_content(      # .aio 가 비동기 인터페이스
            model="gemini-2.5-flash", contents=q
        )
        for q in questions
    ]
    results = await asyncio.gather(*tasks)
    return [r.text for r in results]

LLM 호출은 수 초짜리 I/O다. 순차로 5번 호출하면 15초, gather면 3초다. Google JD의 "latency" 요건이 이런 선택에서 갈린다.

# main.py — Cloud Run 은 PORT 환경변수로 포트를 알려준다 (기본 8080)
import os
from fastapi import FastAPI
from google import genai

app = FastAPI()
client = genai.Client()          # 환경변수에서 설정을 읽는다

@app.get("/healthz")
def healthz():
    return {"status": "ok"}

@app.get("/ask")
async def ask(q: str):
    r = await client.aio.models.generate_content(
        model="gemini-2.5-flash", contents=q
    )
    u = r.usage_metadata
    return {
        "answer": r.text,
        "tokens": {"in": u.prompt_token_count, "out": u.candidates_token_count},
        "cost_usd": cost_of("gemini-2.5-flash", u),
    }

uv 프로젝트 배포에 관한 최신 사실

Cloud Run 소스 배포는 Dockerfile이 없으면 buildpack이 언어를 자동 감지한다. 예전에는 Python에 requirements.txt가 필수라 uv 프로젝트가 곤란했는데, 지금은 pyproject.toml이 정식 지원(GA)된다. uv·Poetry·pip 모두 인식한다.

주의할 점 하나: 두 파일이 다 있으면 requirements.txt가 우선한다. 옛날에 만들어둔 requirements.txt가 남아 있으면 pyproject.toml이 무시되어 "왜 의존성이 안 맞지" 하게 된다.

배포가 끝나면 URL이 출력된다. 그 URL이 이 챕터의 산출물이다.
